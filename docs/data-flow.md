# From field sheet to figures

Use this guide to follow the inputs and results through the complete workshop. Commands run from the downloaded R project. `source()` runs a saved script; a script writes the files listed below. The [start guide](start_here.md) covers setup and file preparation; the [workshop](workshop.md) provides explanations, figures and code.

## Complete workshop

Run every stage with:

```r
source("run_all.R")
```

Or run `source("00_setup.R")`, then run the analysis scripts below, including 04b_kriging in order.

| Stage | Inputs | Run | Results and next use |
| --- | --- | --- | --- |
| Part 1, Steps 1–2: field data and stocks | `data/input/community_cores.xlsm`, selected through `config.R`. | `source("scripts/01_field.R")` | Checked slices, core stocks, descriptive statistics and three figures in `outputs/part1/`. Review `qc_flags.csv` first. Core/layer tables feed the comparison; core stocks and coordinates feed the area analysis. |
| Part 1, Step 3: reference comparison | `outputs/part1/core_stocks.csv`, `layer_stocks.csv` and supplied `data/reference/summary_by_*.csv.gz`. | `source("scripts/02_compare.R")` | Figures and tables in `outputs/part1/comparison/`, grouped by collection, study, ecosystem and region. This provides context; the following maps do not use reference values as extra samples. |
| Part 2A: ecosystem area estimates | `outputs/part1/core_stocks.csv` and `data/aoi/study_area.geojson`, selected through `config.R`. | `source("scripts/03_area.R")` | Hypothetical ecosystem zones, group stock maps, `area_totals.csv` and `area_analysis.rds` in `outputs/part2/area/`. The saved area object feeds Parts 2B–C. |
| Part 2B: distance-based estimates | `outputs/part2/area/area_analysis.rds`, including the AOI, grid and four core stocks. | `source("scripts/04_spatial.R")` | `idw_stock_map.png`, `distance_map.png`, GeoTIFFs and `spatial_analysis.rds` in `outputs/part2/spatial/`. The IDW result feeds Part 3. |
| Part 2C: landscape model and assessment | The same saved area object; simulated landscape predictors and additional simulated stock records generated by the script. | Created by the same `scripts/04_spatial.R` run. | `model_stock_map.png`, `observed_predicted.png`, `holdout_metrics.csv`, simulated records and method totals in `outputs/part2/spatial/`. This is a separate modelling demonstration, not extra field sampling. |
| Part 3: Bayesian update | `outputs/part2/spatial/spatial_analysis.rds`; an invented prior map and assumed prior/new-estimate uncertainties generated by the script. | `source("scripts/05_bayes.R")` | Prior, updated and change maps, uncertainty figure, `bayesian_summary.csv`, grid values and GeoTIFFs in `outputs/part3/`. |

**The connections are:**

```text
Field workbook
  └─ checked slices → core stocks and descriptive statistics
       ├─ core/layer stocks + reference summaries → comparison figures
       └─ core stocks + AOI → ecosystem areas and totals
            ├─ core stocks + distances → IDW map
            │    └─ IDW + prior map + assumed uncertainties → Bayesian update
            └─ simulated landscape data → regression + held-out assessment
```

Figures in the [workshop](workshop.md) have code immediately below them. Running an analysis refreshes its results; opening a saved image alone does not rerun the calculation. After editing an input, rerun that stage and every later stage that reads its results.

Saved R objects (`.rds` files) pass the grid, samples and calculated values between stages. The supplied scripts write and read these files automatically.

The reference tables are aggregate summaries, not raw profiles. Comparisons match quantity, units, depth interval and depth reference. Ecosystem and region comparisons provide broad context rather than a matched statistical test. See [source details](../SOURCES.md).

## Apply the field and IDW steps to your area

The practice route accepts your measurements and AOI without changing calculation functions:

| File to prepare | What it supplies |
| --- | --- |
| `data/input/my_field_data.csv` | One row per soil slice, with the [eight required columns and units](start_here.md#4-prepare-your-own-field-measurements). |
| `data/aoi/my_aoi.geojson` | A polygon containing your sample coordinates; see [boundary instructions](start_here.md#5-add-your-area-of-interest). |

```r
source("run_my_data.R")
```

This saves stocks, statistics and three field figures to `outputs/my_data/part1/`, plus sample and IDW maps to `outputs/my_data/maps/`. It covers the field and IDW calculations. It does not run the complete later analyses. Outputs are separate from the supplied workshop results.

To paste the analysis call instead of using the practice script:

```r
source("00_setup.R")
source("R/course.R")
run_course(
  workbook_path = "data/input/my_field_data.csv",
  aoi_path = "data/aoi/my_aoi.geojson"
)
```

`workbook_path` also accepts the CSV field sheet. `run_example.R` uses the supplied files for this same practice sequence and saves to `outputs/example/`.

The AOI sets the map boundary; it does not supply carbon values or move sample locations. Coordinates and the boundary must describe the same place. At least two different usable locations are required by the IDW code; this minimum does not validate the map.

## Inputs needed to transfer the later analyses

| Analysis | Replace the teaching inputs with |
| --- | --- |
| Reference comparison | Your recalculated layer/core stocks, using compatible units and depth references. The supplied reference summaries can remain as context. |
| Ecosystem area estimates | A suitable ecosystem map and enough representative core measurements for the groups you apply to those areas. |
| Landscape model and assessment | Mapped predictors, suitable stock observations for fitting, and observations held out from model fitting for assessment. |
| Bayesian updating | An appropriate prior map, a new estimate and justified uncertainty for both, with their dependence considered. |

The supplied scripts create hypothetical ecosystem zones, simulated landscape observations and an invented prior to teach these methods. They are part of the workshop analysis. Reusing those invented inputs with another boundary would remain an illustrative exercise. Adapting these later analyses to measured local data requires supplying the corresponding inputs and adjusting their import steps.

## Added kriging and local interfaces

Run `source("scripts/04b_kriging.R")` between the spatial and Bayesian steps. It reads the Part 2A AOI/grid and writes a separate simulation, training variogram, conditional kriging mean/SD and buffered holdout comparison under `outputs/part2/kriging/`. It supplies no likelihood uncertainty to Part 3. `run_all.R` includes this sixth analysis script.

For real local later-stage inputs and exact column names, use [local-inputs.md](local-inputs.md) and `run_local_workshop.R`. The shorter `run_my_data.R` retains its original field-and-IDW purpose. Named generated files and downstream checkpoints are invalidated when their upstream script runs.
